# 产品方向与验收顺序

目标是让家庭成员在放下东西时就能记一笔，在有人能处理时收到一句有用的提醒。最小记录单位是“放在某处的一批商品”。判断功能优先级看三件事：少说几句、库存能否维持准确、提醒后能否完成处理。

## 调研带来的取舍

| 观察 | 项目取舍 |
| --- | --- |
| Grocy 已有商品主档、条码、单位和库存 API。 | 保留轻量批次模型。如果经常重复购买同一商品，再增加扫码或接 Grocy。直接重做完整家庭 ERP 会推迟录入和提醒的改进。[Grocy](https://github.com/grocy/grocy) |
| 鲜知贴允许按存放地管理食品和日用品，还能把待处理物品展示在墨水屏。 | 优先让手机页面和音箱对“在哪里、何时到期”给出一致答案。独立展示屏在有明确需求时再做。[鲜知贴](https://github.com/xueyouluo/fridge_tracker) |
| Grocy Voice Agent 已展示用语音新增和消耗库存，但入口是平板上的语音服务。 | 保留原厂小爱入口，并验证同一笔话只入库一次。网页也应能独立部署和使用。[语音项目](https://github.com/jameshansen/Grocy-ElevenLabs-ElevenAgent-UI) |

## 已交付

批次、位置、到期日与查看日、扣减、撤销和按日在场提醒已实现。待处理视图支持逐批用掉、丢弃或推迟查看，最近操作显示数量变化、时间和撤销状态。本次也新增纯网页启动、可选的米家设备配置、通用 Docker Compose 部署和全量在库 CSV 导出。下载 CSV 需要家庭访问码，内容限于当前库存，不包含家庭密钥、设备 ID、对话记录或已用完的批次。CSV 中的商品和位置本身仍属于家庭数据。

## 接下来验证什么

| 优先级 | 用户问题 | 建议改动和完成条件 |
| --- | --- | --- |
| P0 | 买入、提醒、处理这一整轮，在真实生活里能否完成？ | 先用一笔真实库存走过到期窗口，记录厨房传感器时间、每日预留及现场是否听到。当天再次进厨房不重播，处理后次日不再报；如果未播，页面能分清是时间、人在信号还是输出失败。 |
| P1 | 哪些东西经常买多了？ | 本版已区分使用和丢弃，先积累真实使用记录。若需要汇总，再做按商品和单位的统计。不能用旧版的扣减记录倒推丢弃量。 |
| P1 | 口语说法多，怎样避免记错？ | 以用户自愿提供的脱敏句子扩充测试。优先覆盖一句多商品、跨年日期和挪位置。验收同时检查不应入库的闲聊、缺信息时追问及重复记录只写一次。 |
| P2 | 常买同一物品，能不能少填几项？ | 做条码或商品别名原型，只自动带出名称、常用单位和建议位置，到期日按本批次输入。同条码两次购买、两个日期和位置必须仍有两笔。先试 Grocy API，再决定是否迁移。 |
| 按需求 | 手机在家能否代替厨房有人，或是否需要其他提醒渠道？ | 单独定义“在家”与“在厨房”的有效时长，明确静音时段，再接入同一每日预留逻辑。只有实际需要时才增加账户或云推送。 |

目前现场已确认原厂音箱可以入库并播回执。完整的白天厨房提醒验收仍需要一次真实的临期库存、持续有人与现场听感同时成立。没有为调研采集或发布家庭库存。
